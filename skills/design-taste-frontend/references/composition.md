# Composition and visual craft

Read for substantial layout work or visual redesign, not every label edit. This is a compact synthesis informed by Taste, Anthropic frontend-design, Impeccable, and baseline-ui; see the companion's optional [source record](../../ui-ux-pro-max/references/source-notices.md) for attribution.

## Anchor the surface

Use actual subject matter, content, audience, and current product conventions. For a utility screen, lead with the workspace and familiar controls. For a landing page, lead with a specific offer or convincing artifact. For reading, prioritize measure and rhythm. Brand expression should not replace recognizable navigation and input patterns.

For a redesign, inspect the affected render and relevant source/tokens before choosing changes. Pick the most important actual weakness: unclear hierarchy, disorganized grouping, awkward density, poor type, weak assets, or confused actions. Do not default to another font, more whitespace, a serif headline, a monochrome palette, or a card grid. A small fix does not need a full-site audit or several concepts.

## Make the hierarchy visible

- Make the first reading target and primary contextual action obvious. Use size, weight, alignment, contrast, and spacing together; not extra explanatory captions.
- Define the few text roles the content needs, and reuse them. Avoid near-identical sizes pretending to be different levels, overgrown headings, ornamental all-caps labels, excessive tracking, and hard line breaks that fail on smaller windows. Check actual fonts and scripts, including fallback and clipping.
- Use tighter spacing within a group and more separation between unrelated groups. Match density to the task: efficient data scanning and comfortable reading need different layouts. Whitespace has a grouping role, not a quota.
- Use cards when content is a meaningful bounded unit. Lists, tables, sections, dividers, and unboxed groups can carry structure better. Repetition helps comparison; vary layouts only when the content benefits. Avoid decorative nested frames, identical icon-title-description tiles as universal scaffolding, and fake metrics merely filling space.
- Keep related actions consistent but not equally prominent. Soft interactive surfaces, segments, or rows can establish clickability without a wall of rectangles. Maintain needed input boundaries, readable contrast, semantic feedback colors, and distinct focus/selected states.

## Select an appropriate structure

| Structure | Use when | Check |
|---|---|---|
| Working canvas with local controls | The user operates on content/data | Essential content visible, predictable navigation, scoped actions |
| Split introduction | One message and a useful product/work asset | Reading order, headline wrap, real mobile crop |
| Type-led introduction | A specific message itself carries the purpose | Concrete copy; no obligatory poetic slogan or photo |
| Media-led section | Real evidence explains more than copy | Authentic asset, meaningful crop, text contrast |
| Varied grid | Items have different actual importance | Cell count/content match; no empty filler |
| Repeated list/table | Items must be scanned or compared | Consistent roles, readable numbers, accessible actions |
| Grouped details | Specifications matter but need hierarchy | Keep needed facts; do not hide them only for aesthetics |

## Review the built result

Inspect one representative rendered view at the affected sizes: what reads first, whether the task is obvious, whether the actual content fits, and whether any subtitle, decorative label, card, border, or effect can disappear without losing information. Compare with the existing identity or the supplied reference, not an imagined generic “premium” style. Check relevant long labels, empty/error/loading states, keyboard focus, themes, and reduced motion. Source can establish tokens and semantics; it cannot by itself prove visual quality. Fix concrete defects and recheck only their effects. No detector, subagent, scorecard, or persistent critique report is required.
