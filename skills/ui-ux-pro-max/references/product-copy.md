# Product copy: content, not decoration

Read when designing a text-heavy surface, writing titles, or removing AI-style filler. This applies to web and desktop interfaces in the requested language. Adapted principles are attributed in [source-notices.md](source-notices.md); this guide is an independent compact synthesis, not an upstream skill entrypoint.

## Decide whether text is needed

Read the real interaction path, not isolated strings. Every written element should help identify something, make a decision, take an action, understand a consequential state, or recover. If its removal changes none of these, remove it instead of making it smaller, paler, or hiding it in a tooltip.

- A screen title normally names the actual screen, object, or task. A feature title names what is available. Do not manufacture a poetic promise to fill the top of a utility screen.
- A subtitle must add different, necessary information. Do not follow “导出文件” with a generic line explaining that this is where files are exported.
- A field hint answers a real question about format, eligibility, effect, or consequence. Familiar controls need no narration of how to click them.
- An eyebrow, decorative section number, availability pill, slogan strip, or footer note needs a real semantic purpose. Repeated hierarchy can usually be expressed by spacing and type alone.
- A genuine product benefit, approved brand headline, quotation, technical term, warning, or legal statement can remain. Treat familiar phrases as clues, not a banned-word list.

## Rewrite toward the task

These are contextual examples, not text to paste into every application:

| Weak default | Clearer treatment when accurate |
|---|---|
| 让数据，清晰可见 | 数据概览, or the actual metric/task name |
| 每一次扫描，皆是清晰 | 扫描文档, or omit the headline if the tool is already identified |
| 点击下方按钮，开启高效文件管理之旅 | Keep the action label: 选择文件 |
| 轻松掌控，一切尽在指尖 | Name the actual screen or feature; delete if it adds no information |
| 确认 / 提交 / 继续, where the outcome is unclear | 导出 PDF / 保存设置 / 删除文件, matching the real action |
| 暂无内容，静待美好发生 | Identify first use/no results/failure and provide the appropriate action |

Use concrete nouns and direct verbs rather than mood, vague promises, internal implementation jargon, or ornamental pauses. Do not invent a product benefit, domain, statistic, or operation to make the wording specific. Keep one term for one concept through labels, messages, and results; do not substitute synonyms for style. A sentence-case convention in English should not override another language's normal typography.

## Keep information needed for safe use

Preserve meaningful conditions, negation, units, names, numbers, uncertainty, attribution, and consequences. Do not shorten a different claim into apparent certainty. Keep labels persistent; placeholders show examples rather than replace labels. Make action names specific when context is insufficient.

Errors identify what failed and the available recovery, with a cause only if known. Loading text names the real operation; progress must not be invented. Empty states distinguish first use, no results, permissions, and failure instead of displaying the same motivational phrase. Routine success can be brief and should not add a congratulatory paragraph.

For uncommon professional terms, use short local help accessible on focus and touch as well as hover. Essential requirements and error recovery stay available without opening optional help. Keep visible labels and accessible names aligned. Preserve translatable messages, localization expansion, keyboard access, and readable type; do not force English word limits or unexplained abbreviations onto other languages.

## Finish in one coordinated pass

Read the rendered flow once where available: heading versus subtitle, control versus hint, action versus result. Remove repetitions, check terminology and factual meaning, then fix only identified problems. Do not run a separate document-polishing skill, score text for “AI probability,” generate several rewritten versions, or load all sources just to edit one label. Report actual limitations instead of claiming the copy was user-tested.
