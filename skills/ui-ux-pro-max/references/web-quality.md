# Focused web-interface quality review

Read only for affected web forms, layout, state, or accessibility; use platform equivalents for native apps rather than copying DOM rules. This independently worded checklist is informed by Vercel Web Interface Guidelines and UI Skills; attribution is in [source-notices.md](source-notices.md). No upstream command, output protocol, or mandatory online refresh is imported.

- **Semantics and focus:** reuse accessible project primitives. Actions are buttons, navigation is links, inputs have persistent labels, and icon controls have accessible names. Preserve native keyboard behavior; avoid adding duplicate key handlers to already semantic controls. Dialog focus enters, stays where appropriate, and returns predictably; sticky UI must not hide focus. Keep control perimeters stable through mouse focus/open/selection; replace surrounding outlines/rings/halo shadows and border strengthening with scoped background/label/bottom cues. Preserve visible keyboard focus and system high-contrast indicators; popup boundaries remain distinct from trigger styling.
- **Forms:** use relevant input types, names, autofill and examples without replacing labels. Permit paste and password managers. Keep errors close to the field/action, with useful recovery and an accessible summary when needed. Do not globally disable autocomplete or prescribe one submit/validation pattern regardless of the form.
- **Content stress:** try realistic short and long text, missing values, narrow containers, zoom and localization. Fix the layout's actual cause of overflow rather than masking it with global overflow hiding or truncating indispensable data. Align comparable numbers using appropriate numeric typography and formatting.
- **Hit ownership and notices:** check checkbox/label/row-whitespace behavior against the actual control contract; do not add surprise full-row activation. Normal label activation remains valid unless a user explicitly requests a local checkbox-only target with accessible naming/keyboard support. Routine notices should not reflow the page or require manual close; consequential errors/decisions remain actionable.
- **Layering:** opened menus, dropdowns and dialogs remain legible and distinct from adjacent content; check clipping, placement, dismissal, focus and stacking in the real open state, not only the trigger.
- **Async and navigation:** make loading, disabled, success/error and persistent selection agree with behavior. Preserve user input and valid results where appropriate; stale completions must not replace the current selection. Use shareable URL state for navigation/filter state when the product benefits, not for every temporary UI value. Protect destructive or unsaved work proportionately using existing patterns, including undo where suitable.
- **Delivery and motion:** reserve asset dimensions, prioritize genuinely critical media and defer non-critical work; measure before adding virtualization or another library. Transitions name intended properties rather than everything, remain interruptible, and respect reduced motion. Do not mandate blur, motion, fixed thresholds, or custom scroll behavior.

Check only relevant items in one integrated pass. Report an actionable defect with a verified source location when possible and distinguish source inspection from rendered or measured evidence. Existing project decisions and the user's request govern; do not impose an unrelated framework or run a whole-site audit for a local fix.
